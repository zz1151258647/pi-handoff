# 01 提醒节奏修复

## analysis
- 当前规模阈值 `max(50k, contextWindow*0.5)`；128k 在 64k 触发，1M 在 500k 触发。实际是否展示建议仍由 skill 评估。
- `evaluate defer` 若不传 `next_check`，默认下一轮重评，缺验收或缺后续等未变化时会重复。
- 阶段边界不受冷却控制，不能仅凭规模阈值推断每次提醒来源。

## verification（修复前）
- `tests/simulate.test.js` 只覆盖 1M 的 500k 阈值、1.5 倍再检查，未覆盖较小窗口和未指定时机的暂缓。

## 修复与回归目标
- 较小窗口（不超过 256k）规模检查点设为 80%，大窗口保留 50%；环境变量保持绝对 token 覆盖。
- 未指定时机的 `defer` 默认为下一个压缩检查点；即使本次评估未建议交接，也冷却 3 次自动压缩，避免第 3 次后每次压缩都重评。明确 `next_turn` 仍生效。同步 skill 指导无新事实时不要选择下一轮。
- 回归手动/自动压缩、阶段边界、环境变量覆盖和 1M 窗口。
