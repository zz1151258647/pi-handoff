# 手动项目交接

只在用户执行 `/handoff` 系列命令时工作。讨论或修改本插件不触发交接。自然语言提到“保存进度”时，请简短提示使用 `/handoff`，不要自行保存。

## 命令

| 入口 | 行为 |
| --- | --- |
| `/handoff`、`/handoff 保存`、`/handoff 交接` | 整理当前进度，调用 `handoff_save` 保存到插件已指定的缓存路径 |
| `/handoff 接续`、`/handoff 恢复` | 插件读取唯一的 `handoff.md`；只读核对成功后调用 `handoff_complete` 清理，再继续已授权事项 |
| `/handoff 状态` | 程序显示压缩次数与缓存路径，不调用模型 |
| `/handoff 检查` | 兼容旧命令，仅显示状态，不再评估或建议交接 |

保存与恢复的细节见 [保存与恢复](references/handoff.md)，计数与存储约定见 [计数与缓存](references/counter.md)。

## 不做什么

- 不再使用 `handoff_state`，不登记评估、不输出“交接建议”、不检查冷却、不补漏、不主动建议换会话。
- 压缩结束后的灰色“当前会话已压缩 x 次”由扩展直接显示；模型不回复、不解释、不触发交接。
- 不把交接文件放入项目，不修改 `.gitignore`，不为此提交、推送、发布或删除项目旧文件。
- 不自动创建、打开或切换新会话。接续核对成功后清理用过的存档；核对阻塞、失败或取消则保留。保存成功后只需告诉用户：在新会话执行 `/handoff 接续`。
- 直接调用 `/skill:handoff` 不替代保存命令授权；未由 `/handoff` 发起时，提示先执行该命令。
