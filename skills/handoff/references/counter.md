# 计数与缓存

## 压缩计数

- 监听 Pi 原生 `session_compact` 成功事件；自动压缩和手动 `/compact` 均计入，失败或取消不计。
- 从当前会话的活动分支中统计真实 `compaction` 条目，重启、恢复及 `/reload` 后不会归零；切换分支按该分支历史统计，派生会话包含继承的压缩历史。
- 每次成功后，在消息流附加灰色（主题 `dim` 色）小字：`当前会话已压缩 x 次`。终端不支持调整字号，这里使用正常字号的弱化颜色。
- 使用 `appendEntry` 与 `registerEntryRenderer`，不是模型消息；不占模型上下文、不调用模型、不触发提醒或保存。非终端模式只保存结构化条目，不输出 ANSI 颜色。
- 不再读取或写入旧的 `state/project-handoff/*.json`，`PI_HANDOFF_SIZE_THRESHOLD` 不再生效。旧状态可保留，不影响新逻辑。

## 插件专属缓存

固定位置：

```text
<agent-dir>/cache/project-handoff/handoff.md
```

`agent-dir` 默认 `~/.pi/agent`，可由 `PI_CODING_AGENT_DIR` 指定。缓存不放在插件 Git 安装目录中，避免插件更新、重装或版本切换覆盖档案；也不在业务项目里。只有一个固定的 `handoff.md`，不按项目、目录、分支或会话区分。每次手动保存覆盖旧材料，用于一次接续；接续核对成功后删除；未成功、失败或取消时保留。任务真实工作目录保存在材料中，接续时须核对，不能将改动误写到新会话所在的其他目录。

- `/handoff` 整理本次任务并覆盖单份存档，单次授权 `handoff_save` 原子写入与回读。
- `/handoff 接续` 读取固定存档，核对成功后调用单次授权的 `handoff_complete` 清理。单纯读取、核对阻塞或取消不会删除；若已被其他会话更新则拒绝删除新材料。不在每次启动或普通聊天时自动加载。
- 下次 `/handoff 交接` 从当前会话从零生成，不合并旧档；如果上次接续失败留下存档，新的显式保存会覆盖它。
- `/handoff 状态` 显示实际路径及压缩次数，不创建缓存。
- 每次保存会在 Markdown 开头写入唯一修订号（HTML 注释），即使正文相同或恢复为旧正文，也视为新存档；清理核对包含修订号的完整快照，防止旧接续误删新档。
- 存档发生变化时拒绝覆盖；同时写入以独占锁拒绝。异常退出可能留下 `handoff.md.lock`，确认没有保存任务运行后可手动移除该锁，再执行 `/handoff`。锁、临时文件均在缓存中。
- 新建存档与临时文件使用仅当前用户读写权限（Windows 的最终权限仍取决于目录 ACL）。缓存不应存凭据，且不是跨机器备份。
- 仅为保存或更新存档创建缓存。压缩、查询、普通启动、保存、接续和清理均不写项目文件，不需要添加 `.gitignore`。
- 卸载插件不会自动清除缓存；可自行备份或删除 `<agent-dir>/cache/project-handoff/`。

## 验证

`node tests/simulate.test.js` 在独立临时目录中模拟命令、事件、存档、恢复和渲染，不联网、不调用模型。模拟验证不等于真实 TUI 验收；修改安装副本后运行 `/reload`，再以一次真实 `/compact` 检查灰色计数。
